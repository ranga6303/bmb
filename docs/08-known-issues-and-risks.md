# Known Issues And Risks

| Severity | File | Issue | Suggested fix |
|---|---|---|---|
| High | `src/main/resources/application.properties` | `resend.api.key` is hardcoded as a literal secret while README claims secrets are environment-managed. | Replace with `resend.api.key=${RESEND_API_KEY}` and rotate the exposed key. |
| High | `.env`, `seed-data.ps1` | Local and Railway-style database/email/admin secrets are present in workspace files; `seed-data.ps1` also embeds a MySQL password in command arguments. | Rotate exposed credentials, keep `.env` local only, move seed credentials to environment variables or prompt input. |
| High | `src/main/java/com/example/demo/controller/TestController.java` | `/test-password` returns the submitted password, submitted hash, and a newly generated hash. It is admin-only but still creates a sensitive credential disclosure/debug endpoint. | Remove the endpoint outside tests or guard it behind a non-production profile. |
| High | `src/main/java/com/example/demo/service/DeviceVerificationService.java` | Signature verification prints signed payload, signature prefix, public key prefix, and lengths to stdout. This leaks security material into logs. | Replace `System.out.println` calls with no logging or minimal structured debug logs disabled in production. |
| Medium | `src/main/java/com/example/demo/service/SessionService.java` | First attendance mark can bind `registeredDeviceId` without requiring `publicKey`, `signedPayload`, or `deviceSignature`. If no key is stored, later marks from the same device ID also skip signature verification. | Require public key registration and signature verification on first device bind; require signatures for every student mark after migration. |
| Medium | `src/main/java/com/example/demo/service/SessionService.java` | `expiryTime` is set to `now.plusMinutes(60)`, while README says the active session window is three minutes. This weakens the anti-abuse window relative to documented behavior. | Align implementation and docs; make the duration configurable, for example `app.sessions.active-window-minutes`. |
| Medium | `src/main/java/com/example/demo/entity/Attendance.java` | Final attendance has no unique constraint on `(session_id, student_id)`. A retry or race around approval could create duplicate rows. | Add a unique constraint and make approval idempotent or guarded by status/version checks. |
| Medium | `src/main/java/com/example/demo/service/AuthService.java` | `resetPassword()` updates `lastPasswordChange` but does not revoke active refresh sessions. Old refresh tokens can still rotate to new access tokens unless rejected by other logic. | Revoke all active `UserSession` rows after password reset. |
| Medium | `src/main/java/com/example/demo/service/AuthService.java` | `LoginRequest.deviceId` is accepted by the API but ignored in `loginInternal()`. New `UserSession.deviceId` and the JWT `deviceId` claim are populated from `User.registeredDeviceId`, not the request. This can surprise clients and makes the existing device-ID login test inconsistent with the implementation. | Either remove `deviceId` from login requests or explicitly validate/use it according to the intended device-binding design. |
| Medium | `src/main/java/com/example/demo/exception/GlobalExceptionHandler.java` | Catch-all `RuntimeException` returns `ex.getMessage()` to clients. Internal exception text may leak implementation or database details. | Return a generic message for unhandled exceptions and log details server-side only. |
| Medium | `src/main/java/com/example/demo/config/SecurityConfig.java` | CORS allows all origins and all headers. With Bearer tokens this is less dangerous than credentialed cookies, but it still broadens browser attack surface. | Restrict allowed origins per environment. |
| Medium | `src/main/java/com/example/demo/service/DeviceChangeService.java` | Approving a device change sets `registeredDeviceId` without checking whether another user already owns `newDeviceId`. Admin UI reports conflicts, but the service does not enforce uniqueness. | Enforce no conflicting owner in `approveRequest()` or define an explicit transfer workflow. |
| Medium | `seed-data.ps1` | The seed script calls `/admin/users`, but no current controller implements that endpoint. It cannot seed users against this code as written. | Update the seed script to match actual APIs or add/import a dedicated admin user creation endpoint. |
| Low | `src/main/java/com/example/demo/service/SessionService.java` | `ensureDeviceChangeRequestExists()` is unused dead code. | Remove it or wire it into the device mismatch flow intentionally. |
| Low | `src/main/java/com/example/demo/service/AuthService.java` | `resetFailed(User user)` is unused dead code. | Remove it or use it in login success path. |
| Low | `src/main/java/com/example/demo/controller/HodController.java` and `DepartmentController.java` | HOD department is inferred from the first teacher assignment. If an HOD has assignments across departments, access/report behavior depends on list ordering. | Add an explicit department field or HOD-department mapping. |
| Low | `src/main/java/com/example/demo/controller/AdminController.java` | Several admin operations implement business rules directly in the controller. | Move admin mapping operations into a transactional service for clearer validation and testing. |
| Low | `README.md` | Documentation references old doc filenames and claims no hardcoded credentials, but the current project has new requested docs and a hardcoded `resend.api.key`. | Update README links and security notes after the new docs are accepted. |

## Dependency Notes

The project uses Spring Boot `4.0.3`, Java 17, JJWT `0.12.7`, `dotenv-java` `3.0.0`, and `resend-java` `3.1.0`. I did not perform a live vulnerability database lookup because the task was completed from the local codebase; treat dependency vulnerability status as requiring a separate `mvn dependency-check`/SCA scan.

## Test Coverage Gaps

Current tests cover context loading, `/test-password` authorization, and JWT device ID mismatch behavior. There are no tests for registration OTPs, password reset revocation, session lifecycle approval idempotency, HOD access boundaries, device change conflict enforcement, or ECDSA attendance marking.
